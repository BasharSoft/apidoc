# apidoc Wiki

`apidoc` is BasharSoft's **fork of the open-source apiDoc generator** (version `0.17.6`, original author Peter Rottmann, MIT). It is a Node.js command-line tool: it reads `@api...` comments from source files and writes a static HTML documentation site (Handlebars + Bootstrap + jQuery template).

**How it serves Wuzzuf:** it builds the **old API documentation of `wuzzuf-platform`**. `wuzzuf-platform/package.json` lists `"apidoc": "https://github.com/BasharSoft/apidoc.git"` as a dev dependency, and its `package-lock.json` pins this exact commit (`f95145d`). The `wuzzuf-platform` Docker build runs `yarn run gulp old-api-doc`, which calls this tool on `app/Http/Controllers`, `app/Representations` and `apiDoc/EntitiesDocs` (239 PHP files carry `@api` comments) and writes `public/docs`. A newer Swagger/OpenAPI page (`gulp api-doc`, `public/api-docs`) is built next to it.

The only BasharSoft change visible in the code is the dependency switch: `package.json` points `apidoc-core` at `https://github.com/BasharSoft/apidoc-core.git` instead of the npm package. No Wuzzuf-specific code was found in `lib/` or `template/`. Without git history, other small differences from upstream 0.17.6 cannot be ruled out.

This wiki was written from the source code (`master` at `f95145d`). The existing README/docs weren't used. The [code map](code-map/index.md) was generated with graphify.

> **Read [Known issues](known-issues.md) first.** `wuzzuf-platform`'s `yarn.lock` does not resolve to this repo: it points to a personal fork (`SherifMedhat/apidoc`) over the retired `git://` protocol, and the Dockerfile uses `yarn install`. The tool and its template are from 2017 (jQuery 2.2.1, Node 6 era).

## Glossary

| Term | Meaning |
|---|---|
| **`@api` block** | A doc comment like `@api {get} /jobs/:id Get job` followed by `@apiParam`, `@apiSuccess`, etc. |
| **`apidoc.json` / `_apidoc.js`** | Project config (name, title, URL) and shared `@apiDefine` blocks |
| **Template** | The HTML/JS site copied to the output folder and filled with `api_data.js` / `api_project.js` |
